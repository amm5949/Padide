# سیستم مدیریت مجوزها — پدیده پایدار

نمونه رابط کاربری **Next.js App Router + TypeScript + Tailwind v4 + shadcn-compatible UI + RTL + PWA-ready** برای دو نقش کاربر و مدیر.

> هشدار: این یک **نسخه نمایشی UI** است، نه سامانه بانکی عملیاتی. ورود نقش‌ها، درخواست‌ها و تصمیم‌های مدیریتی Mock هستند. هیچ پرونده یا PDF در این پروژه به طور پیش‌فرض روی سرور ذخیره نمی‌شود.

## اجرا

نیازمندی‌ها: Node.js 20.9+ (برای Next.js 16، نسخه 20.9 یا بالاتر؛ ترجیحاً Node 22) و npm.

```bash
npm install
cp .env.example .env.local
npm run dev
```

آدرس `http://localhost:3000` را باز کنید. در `/login` نقش **کاربر** یا **مدیر** را انتخاب کنید. این انتخاب **احراز هویت نیست** و فقط برای نمایش مسیرهای مختلف طراحی شده است.

ساخت نسخه نهایی و بررسی:

```bash
npm run typecheck
npm run build
npm run start
npm run test:e2e
```

**وضعیت تست در زمان تحویل:** ساختار فایل‌ها، ارجاعات داخلی و نحو TypeScript به صورت ایستا کنترل شده‌اند؛ به علت دسترسی‌نداشتن به رجیستری npm در محیط تولید فایل، نصب پکیج‌ها، اجرای Next، بیلد و تست مرورگری هنوز انجام نشده‌اند. دستورات بالا باید روی محیط دارای اینترنت اجرا و نتیجه‌شان بررسی شود.

## مسیرها

| نقش | مسیرها |
| --- | --- |
| عمومی | `/login` |
| کاربر | `/user`, `/user/credit/new`, `/user/checks/new`, `/user/statements/new`, `/user/requests`, `/user/requests/[id]`, `/user/settings` |
| مدیر | `/admin`, `/admin/credit`, `/admin/credit/[id]`, `/admin/checks`, `/admin/checks/[id]`, `/admin/statements`, `/admin/statements/[id]`, `/admin/settings` |

کد مسیرها در `app/`، اجزای رابط در `components/`، مدل‌ها، داده‌های نمایشی و اعتبارسنجی در `lib/` هستند. مستندات نیازمندی، معماری، ابهام‌ها و QA را در `docs/PRODUCT_SPEC_FA.md` ببینید.

## فرم‌ها و داده‌ها

- فرم اعتبار شامل **۳۸ فیلد منبع**، چهار مرحله ورود اطلاعات و یک مرحله بازبینی است.
- فرم تأیید چک شامل **۱۲ فیلد منبع** است.
- رکوردهای نمونه در `lib/mock-data.ts` هستند، نه API.
- وضعیت‌های درخواست، صرفاً Mock و از `lib/status.ts` هستند.
- **واحد پول**، **تقویم/تاریخ**، **راس چک**، **عملیات محاسبه**، **گردش‌کار تأیید** و **قوانین الزامی** باید با کارفرما مشخص شوند؛ کد آن‌ها را به‌عنوان منطق تجاری واقعی فرض نکرده است.
- فیلدهای دارای ستاره در فرم‌های نمایشی فقط برای تست حداقلی UX هستند.

## آپلود PDF

فرم `/user/statements/new` نوع MIME، پسوند، خالی‌بودن و حجم فایل را در مرورگر کنترل می‌کند. محدودیت پیش‌فرض `10MB` است و با `NEXT_PUBLIC_MAX_PDF_MB` تغییر می‌کند.

تا زمانی که `NEXT_PUBLIC_STATEMENT_UPLOAD_ENDPOINT` تنظیم نشود، دکمه ارسال به سرور غیرفعال است. در صورت تنظیم، `XMLHttpRequest` با `POST multipart/form-data` به آدرس **نسبی و هم‌مبدأ** درخواست می‌دهد و در صورت پشتیبانی مرورگر/سرور، پیشرفت واقعی ارسال را نمایش می‌دهد. این پروژه سرویس دریافت یا ذخیره PDF ندارد.

API واقعی باید تشخیص PDF از محتوای باینری، محدودیت حجم سمت سرور، ضدبدافزار، ذخیره خصوصی، مجوزها، نرخ درخواست، CSRF، لاگ امنیتی و آدرس دانلود کوتاه‌عمر را پیاده‌سازی کند.

## احراز هویت و امنیت

`lib/demo-auth.ts` صرفاً وجود کوکی آزمایشیِ قابل تقلید را در Server Layout بررسی می‌کند. این مدل **هرگز نباید برای امنیت عملیاتی استفاده شود**. قبل از استقرار باید:

1. ورود واقعی و نشست امضاشده یا توکن قابل‌اعتبارسنجی پیاده‌سازی شود.
2. RBAC و مالکیت منابع در Server Actions، Route Handlers و API/DB اجرا شود، نه فقط Layout/UI.
3. دسترسی به هر درخواست و هر PDF در سمت سرور براساس شناسه کاربر کنترل شود.
4. تصمیم‌ها و وضعیت‌ها در تراکنش ثبت و Audit Log غیرقابل‌دست‌کاری ایجاد شود.
5. استفاده از HTTPS، CSRF protection، rate-limit، security headers، monitoring و سیاست نگهداری اطلاعات الزامی است.

## PWA

`app/manifest.ts` مانیفست، آیکون‌ها در `public/icons` و `public/sw.js` یک offline fallback محدود فراهم می‌کنند. SW فقط صفحه‌ی عمومی آفلاین و دو آیکون را precache می‌کند؛ **صفحات خصوصی، پاسخ API و PDFها را cache نمی‌کند**. Service Worker فقط در build production ثبت می‌شود. برای قابلیت نصب باید سایت روی HTTPS یا localhost باشد و آیکون‌ها و manifest معتبر باشند.

## RTL و تم

`html lang="fa" dir="rtl"`، کلاس‌های منطقی `start/end` و `components.json` با `rtl:true` استفاده شده‌اند. تم‌های روشن، تاریک و سیستم با `next-themes` مدیریت می‌شوند. ترجیح هر نقش در localStorage با کلید مجزا ذخیره می‌شود؛ برای همگام‌سازی بین دستگاه‌ها لازم است به پروفایل سروری متصل شود. فونت Vazirmatn به‌صورت نام خانواده در CSS در نظر گرفته شده است؛ برای استقرار، نسخه دارای مجوز را طبق فرآیند سازمان self-host کنید.

## وضعیت خروجی

پروژه، **کد قابل توسعه** است و موارد زیر بدون بک‌اند قابل آزمون‌اند: مسیرها، رابط فرم و اعتبارسنجی اولیه، جست‌وجو/فیلتر/صفحه‌بندی، تصمیم نمایشی، سوئیچ تم و انتخاب PDF. ادعای اتصال به داده‌های واقعی، ثبت واقعی درخواست یا پذیرش واقعی سند ندارد.

## پیش‌نمایش بصری بدون نصب

فایل `preview.html` را می‌توان مستقل در مرورگر باز کرد. این فایل فقط برای مرور بصری چند نمونه صفحه، نقش‌ها، تم روشن/تاریک و چیدمان موبایل طراحی شده است؛ **جایگزین پروژه Next.js نیست** و عملیات آن واقعی نیست.
